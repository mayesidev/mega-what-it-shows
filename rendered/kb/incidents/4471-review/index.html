Failure paths and verification

The shared parser reads dates month first even for tenants whose locale writes the day first. An intended 7 April can become 4 July. This is the majority cause in #4471, seen through app, email, and booking-v2 forms. Fix date interpretation at the parser boundary using the tenant’s locale, with tests for ambiguous and unambiguous dates.

A separate booking-v3 form prints MM/DD/YYYY to day-first tenants, while interpreting their input in the tenant’s day-first order. Users following that hint can create a different date from the one intended. Correct the hint and align its examples and validation with the form’s parser. A shared-parser fix alone does not establish that this is fixed.

Use tenant locale, booking-form version, and report channel to determine these groups. Browser locale and intake tags are guesses, not the tenant’s settings. Some intake tags disagree with the computed cause. Source: src/lib/kb/causes.ts, locales.ts, and tenant JSON files; the complete report membership is in evidence/analysis.json.
