booking-v3 date hint contradicts day-first tenant parsing (33 reports)

## Scope

**33 unique reports** merged into support ticket #4471, from the 4 October 2026 course export. This is a snapshot count, not a live support total.

## Failure path

For day-first tenants using booking-v3, the form prints MM/DD/YYYY but reads the input in the tenant locale order. A person following that hint can select a different date from the one intended. Only the form channel on booking-v3 is assigned to this cause; app/email from the same tenant do not belong here.

## Evidence

- Received: 2026-04-17 through 2026-09-22.
- Affected tenants in this export: 3.
- Source: `src/lib/data/reports-4471.json`; tenant configuration: `src/lib/data/tenants/`; classification: `src/lib/kb/causes.ts` and `locales.ts`.
- Reproduce counts with `npm ci --ignore-scripts` then `npm run build && npm run check`.
- Full membership and examples: `evidence/analysis.json`, group `hint`.
- KB source: `src/routes/kb/incidents/4471-review/+page.svx`; rendered page: `rendered/kb/incidents/4471-review/index.html`.

The export has 427 rows but 412 unique report IDs; overlapping pages repeat 15 rows. Count IDs once and classify by tenant locale, form version, and channel, not subject or browser intake tag. The two groups are disjoint and cover those 412 IDs.

## Fix and acceptance evidence

Make the date hint, example, validation, and parser agree with the tenant locale. Reproduce through booking-v3 for alder.physio, copper.studio, and pale.harbour. Test an ambiguous date, an unambiguous date, and the month-first tenant case. A shared-parser fix alone is not evidence that this form defect is resolved.
